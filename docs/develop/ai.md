# 用 AI 工具协助

可以用 AI 工具写代码、查问题。规矩只有两条：

- **改动要让 AI 自己测过**：编译、跑单元测试，能开实例的就开实例看结果，在 PR 里写明测了什么、结果如何。
- **不要把账号、密钥、私人路径交给 AI 工具。**

## 按活选模型

| 什么活 | Claude | GPT（Codex） |
|---|---|---|
| 模拟器本体、执行桥、崩溃根因 | Opus 5.5，推理开高 | GPT-6 Astra，High 或 Extra High |
| 管理器的普通功能和界面、输入法、CI、脚本 | Sonnet 5.5 | GPT-6.1 Sol，Medium |
| 自更新、签名、发版 workflow、权限这类涉及安全的 | Sonnet 5.5 写，Opus 5.5 审，最后由人审 | GPT-6.1 Sol 写，GPT-6 Astra 审，最后由人审 |
| 跑测试、看日志、盯进度、写文档 | Sonnet 5.5 | GPT-6.1 Terra |
| 整理日志、批量改格式、核对清单 | Haiku 5.5 | GPT-6 Luna |
| 合 PR 前的审查 | Opus 5.5，不要和写代码的是同一个会话 | GPT-6 Astra，同样不要和写代码的是同一个会话 |

- 模型名以 2026 年 10 月为准，两家更新都快，换代后按同样的分层选：难的给最强的模型、推理开高；规则清楚的给中档模型；纯搬运给便宜的模型。
- GPT 这边 GPT-6.1 Sol 接近 Astra、便宜不少，适合长时间的编码；预算紧时，本体和执行桥也可以用 Sol 加 Extra High。
- 各分区更具体的建议写在[分区一览](./overview)和各分区页面的「模型建议」里。

## 给 AI 的提示

- 把要守的规矩直接告诉它：关模拟器先 sync；adb 用私有端口、不碰 5037；不改游戏文件、不绕过游戏的保护；游戏里不抽卡、不买东西。
- 让它先取证再下结论。以前误判过的几次（把 fork 死锁当成网络慢、把硬杀弄坏的文件当成 CDN 连不上），都是没拿现场就猜。见[常见问题怎么查](./troubleshooting)。
- 对比性能时让它交替多轮跑，只跑一次比一次不算数。
